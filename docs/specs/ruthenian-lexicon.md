# Spec: `ruthenian-lexicon`

Phase 3. Depends on `ruthenian-core`, `ruthenian-orthography`.

## 1. Purpose

The lexical entry schema every other crate agrees on: what a word *is* in this
system, what we know about it, and where that knowledge came from.

It exists as its own crate for one structural reason: **the extractor must not
depend on the artifact it generates.** If these types lived in the facade, then
`ruthenian-extract` — whose job is to write the facade's tables — would depend on
the facade. That inversion works until the first refactor and then does not. A
zero-dependency schema crate lets `extract`, `ruthenian` and `eval` agree without
any of them owning the others.

Wrong to put here: rules (they are in `core`), data (it is generated by
`extract`), or lookup logic (it is in the facade). This crate is types, their
invariants, and the serialization format.

## 2. Public API sketch

### The key is composite

`EntryKey` is built from the lemma plus the properties that actually distinguish
the homographs — not from a sequence number:

```rust
pub struct EntryKey {
    pub lemma: Ruthenian,       // unstressed, for lookup ergonomics
    pub pos: Pos,
    pub disambiguator: Disambiguator,   // the minimal class facts that separate homographs
}

pub enum Disambiguator {
    None,                                    // the lemma is unique in its pos
    Noun { gender: Gender, class: NounClass },
    Verb { aspect: Aspect, class: ZaliznyakVerbClass },
    Adj  { class: AdjClass },
}

impl EntryKey {
    /// "voda", "voda.f.1a", "pisatj.ipf.6c" — stable, parseable, human-typable.
    pub fn display(&self) -> String;
    pub fn parse(s: &str) -> Result<Self, KeyError>;
}
```

Two properties this buys, and they are the reason for the choice:

1. **Stable across dump refreshes.** A key is derived from linguistic facts, so a
   newer dump cannot silently move a key to a different word the way a
   sequence-numbered scheme can. A key changes only when the facts change, and
   that is a semantic change announced in the changelog.
2. **Self-describing.** `pisatj.ipf.6c` says what it is. A user reading CLI
   output or a bug report can tell which word is meant without a lookup.

The costs, accepted and documented: keys are longer, and `Disambiguator::None`
must be computed globally — a lemma is only unambiguous if nothing else in the
lexicon shares its (lemma, pos). That makes key assignment a whole-lexicon
operation, not a per-record one, which the extractor must be built for.

```rust
pub struct Entry {
    pub key: EntryKey,               // composite; see above
    pub pos: Pos,
    pub lemma: Ruthenian,            // citation form, Ruthenian script
    pub source_lemma: Cyrillic,      // exactly as attested, stress marks intact
    pub inflection: Inflection,      // the class + what the rules cannot predict
    pub provenance: Provenance,
    // NOTE: senses are deliberately NOT inlined here. See §2a.
}

/// One dictionary sense, as the source structures it. Stored in full: a Russian
/// lemma commonly carries ten or more, and collapsing them to a headline gloss
/// throws away the part a human actually wants.
pub struct Sense {
    pub gloss: String,               // English, from the dump, verbatim
    pub tags: Vec<SenseTag>,         // vulgar, obsolete, figurative, dialectal, ...
    pub topics: Vec<String>,         // subject-field labels where the source gives them
}
```

### 2a. Senses live in their own generated blob

Full structured senses are stored, but **not inside `Entry` and not compiled into
any crate**. They go in a separate generated file, `senses.rdb`, produced by
`ruthenian-extract` alongside the lexicon. A consumer obtains the bytes whichever
way suits it:

```rust
// Compile-time: the CLI embeds the blob and stays a single self-contained binary.
static SENSES: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/senses.rdb"));
let idx = SenseIndex::open(SENSES)?;

// Runtime: a tool that would rather not carry megabytes reads the file instead.
let bytes = std::fs::read(path)?;
let idx = SenseIndex::open(&bytes)?;

pub struct SenseIndex<'a> { .. }
impl<'a> SenseIndex<'a> {
    pub fn open(bytes: &'a [u8]) -> Result<Self, SenseError>;   // validates header, no full parse
    pub fn get(&self, key: &EntryKey) -> Option<SenseList<'a>>; // binary search, zero-copy
}
```

The format is this crate's to define, and it is shaped by the `include_bytes!`
use case: a header carrying the schema version and dump fingerprint, then a
sorted key index of `(key, offset, len)`, then the concatenated sense payloads.
`open` validates the header only; `get` binary-searches the index and borrows
straight out of the buffer. Nothing is deserialized until asked for, so embedding
the blob costs binary size and nothing else.

Keeping senses out of `Entry` is what makes the inflection lexicon stay small,
diffable and reviewable — the thing you actually read when a form looks wrong —
while the prose that dominates the byte count sits where it can be excluded.

```rust
// (Entry, continued — the type above, shown here for context)

pub enum Inflection {
    Noun {
        class: NounClass,            // stem class + accent pattern + reducible
        gender: Gender,
        animacy: Animacy,
        number_defect: Option<NumberDefect>,   // PluraleTantum | SingulareTantum
        indeclinable: bool,
        relational_adj: Option<Ruthenian>,
    },
    Adj { class: AdjClass, short_forms: ShortForms, comparative: Option<Ruthenian> },
    Verb {
        class: ZaliznyakVerbClass,
        aspect: Aspect,
        partner: Option<EntryKey>,   // the aspect pair, resolved to a key not a string
        transitivity: Option<bool>,  // None = the source carries no marker
        reflexive: bool,
        principal_parts: PrincipalParts,
        gaps: SlotSet,               // slots the source marks "-"
    },
}

/// Exactly the forms the rules cannot derive from (stem, class). Empty is the
/// common case and is meaningful: "the class is sufficient".
pub struct PrincipalParts {
    pub present_stem: Option<Ruthenian>,
    pub overrides: Vec<(VerbSlot, Ruthenian)>,
}

pub struct Provenance {
    pub source: Source,              // Wiktionary { page, revision }
    pub confidence: Attestation,     // Attested | Inferred { from: RuleId }
}

/// The one place "where did this form come from" is expressed.
pub enum Origin {
    Attested,                        // the source lists this exact form
    RuleDerived,                     // the rule engine produced it, unmodified
    Regularized(RuleId),             // a declared departure from standard Russian
}

pub struct Form {
    pub text: Ruthenian,
    pub slot: Slot,
    pub origin: Origin,
    pub trace: Trace,
}
```

`Form` lives here rather than in the facade because both the facade and the
evaluator return it, and neither should own the other's vocabulary. It is the
type the whole system converges on: the CLI prints it, the evaluator scores it,
the tables are compressed against it.

`partner: Option<EntryKey>` rather than `Option<String>` is law 12 in miniature —
an aspect partner is a reference to another entry, and storing it as a string
invites everyone downstream to re-resolve it differently.

## 3. Inputs and outputs

In: constructed by `ruthenian-extract`. Out: consumed by `ruthenian` and
`ruthenian-eval`.

Two on-disk artifacts, both owned by this crate's format definition:

- **`lexicon.jsonl`** — one `Entry` per line, sorted by key, deterministic field
  order. Inflection data only; the human-inspectable intermediate.
- **`attested.tsv`** — `(key, slot, form)` triples, the evaluator's ground truth,
  separated from the lexicon because it is large, write-once, and never consulted
  at runtime.
- **`senses.rdb`** — the binary sense blob described in §2a, embeddable with
  `include_bytes!` or readable at runtime.

Both carry a header record with the schema version and the dump fingerprint.
Loading an artifact whose schema version is unknown is an error, not a
best-effort parse.

## 4. Data owned

The schema and its versioning. Not the data itself — that is generated. This
crate is the single canonical *owner of the shape*; `extract` is the single
canonical *producer of the content*.

## 5. Dependencies allowed

`ruthenian-core`, `ruthenian-orthography`, and **`serde` only** (with `derive`).
No `serde_json` — serialization format helpers belong to the crates doing I/O.
The zero-third-party rule is relaxed exactly this far and no further, and the
reason is written in the `Cargo.toml`.

## 6. Invariants

1. Every `Entry` is constructible only through a builder that requires
   provenance. An entry with no source cannot exist.
2. `lemma` and `source_lemma` round-trip through `ruthenian-orthography`.
3. `EntryKey` is unique across the lexicon; two entries with the same key is a
   load error, not a last-one-wins merge.
3a. `EntryKey::parse(k.display()) == k` for every key, and `Disambiguator::None`
   is used **only** when the (lemma, pos) pair is genuinely unique in the
   lexicon — checkable globally, and the check is what keeps bare keys honest.
4. `PrincipalParts` contains only what the rules cannot predict. Storing a form
   the rule engine already produces is a **schema violation**, checkable, and the
   check is what keeps the artifact small.
5. `gaps` and `Policy::attested()` agree: a slot in `gaps` yields `None` from the
   facade under the attested policy.
6. Serialization is deterministic — same `Entry`, same bytes, on any platform,
   with sorted keys and no floating point.
7. `Origin::Regularized` always names a `RuleId` that exists in the core
   registry.

## 7. Guards

| Name | Invariant | Failure witness | Status | Cost | Owner |
|---|---|---|---|---|---|
| `entry_requires_provenance` | Inv. 1 | Add a public constructor bypassing the builder | required | ms | crate |
| `key_uniqueness` | Inv. 3 | Emit two entries with the same key; loading must error, not overwrite | required | ms | crate |
| `key_roundtrip_and_minimality` | Inv. 3a | Assign `Disambiguator::None` to a lemma that has a homograph, or add a class field that does not distinguish anything | required | seconds | crate |
| `key_stable_across_refresh` | Keys derive from facts, not order | Introduce a sequence number into `EntryKey`; re-keying a shuffled input produces different keys | required | seconds | crate |
| `principal_parts_minimal` | Inv. 4 | Store a rule-predictable present stem; the check recomputes and rejects it | required | seconds | crate |
| `gaps_match_policy` | Inv. 5 | Mark a slot as a gap while the attested policy still emits a form | required | seconds | crate |
| `serialization_deterministic` | Inv. 6 | Swap a `BTreeMap` for a `HashMap` in any serialized structure | required | ms | crate |
| `schema_version_enforced` | §3 | Load an artifact with a bumped version; must error | required | ms | crate |
| `ruleid_resolves` | Inv. 7 | Reference a `RuleId` the core registry does not define | required | ms | crate |
| `roundtrip_lemma_scripts` | Inv. 2 | Store a `lemma` that is not the transliteration of `source_lemma` | required | ms | crate |
| `senses_are_verbatim_english` | Sense text is never transliterated or normalized | Run `to_latin` over a gloss; the check finds Ruthenian digraphs in English prose | required | ms | crate |
| `senses_not_in_entry` | §2a — `Entry` carries no sense text | Add a `gloss` field to `Entry`; the lexicon JSONL size check and the type-shape test both fail | required | ms | crate |
| `sense_index_zero_copy` | `SenseIndex::open` validates the header without parsing payloads | Deserialize the whole blob in `open`; the timing/allocation assertion on a large fixture fails | required | ms | crate |

Eight guards. `principal_parts_minimal` is the one that matters most: it is the
mechanical enforcement of law 2 at the data layer, and without it the lexicon
silently grows into a full form table.

## 8. Out of scope

- Producing entries → `ruthenian-extract`.
- Answering questions about entries (lookup, fallback, homograph resolution) →
  `ruthenian`.
- Scoring entries → `ruthenian-eval`.
- Any I/O beyond `serde` derives. This crate defines formats; it does not open
  files.

## 9. Done criteria

- The eight guards present, each demonstrated to fail under its witness.
- The schema expresses every metadata field the dump actually carries — verified
  against real records, not assumed: gender, animacy, stem class, accent pattern,
  reducible-stem marker, relational adjective, aspect, aspect partner,
  transitivity, Zaliznyak class, principal parts, paradigm gaps.
- A worked example in the crate docs: one noun and one verb entry, complete, with
  the real values taken from the records cited in `ruthenian-extract.md`.
- Zero dependencies beyond `serde`; `#![forbid(unsafe_code)]`.

## 10. Closed decisions

- **Homograph keying: composite keys carrying the disambiguating class**, not
  `_n` sense suffixes. See §2. The consequence for other crates: the facade's
  `resolve` maps a bare surface lemma to candidate keys, key assignment is a
  whole-lexicon pass in the extractor, and the stability contract in
  `DIRECTION.md` is stronger than it would have been — keys survive a dump
  refresh.

- **`Form` lives here**, not in the facade, so the evaluator can consume it
  without depending on generated tables and the extractor can speak the same
  vocabulary.

- **Senses are stored in full, structured** — gloss, tags and topics per sense,
  in source order. A Russian lemma routinely carries ten or more senses and the
  distinctions between them are the part a human wants; collapsing them to a
  headline gloss would make `ruth lookup` a grammar table rather than a
  dictionary entry. Three consequences that follow, and must be handled rather
  than discovered:

  1. **The artifact grows substantially.** Sense text will dominate the lexicon
     JSONL — likely by an order of magnitude over the inflection data. Report
     the split (bytes of inflection vs bytes of sense) so the cost is visible.
  2. **This is redistributed Wiktionary prose, not derived data.** Inflection
     facts are arguably facts; gloss text is authored content under CC BY-SA 4.0
     + GFDL. `ATTRIBUTION.md` must say so explicitly, and the requirement is
     attribution *and* ShareAlike on anything that carries the glosses onward.
  3. **Sense text is not Ruthenian and must never be transliterated.** It is
     English, stored verbatim. A guard enforces that no orthography conversion
     touches it.

- **Senses live in a generated blob, not in any crate.** `senses.rdb` is produced
  by the extractor and consumed either by `include_bytes!` at compile time or
  `fs::read` at runtime — the CLI takes the first route and stays a single
  self-contained binary; a library consumer that does not want the prose simply
  does not embed it. No cargo feature, no runtime path lookup by default, no
  megabytes of English in a crate whose job is inflection. See §2a.
